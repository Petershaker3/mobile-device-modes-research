# Android Device Modes & Windows Toolkit Research

مرجع بحثي منظم لدراسة أدوات Windows الجاهزة والمكونات التقنية اللازمة للتعامل مع هواتف Android عبر أوضاع الاتصال المختلفة، وقراءة معلومات الأجهزة، وإدارة التطبيقات والشبكة، وتشخيص تعريفات USB وإصلاحها.

> **حالة المستودع:** بحث وتوثيق ومقارنة. ليس برنامجاً منفذاً، ولا يعني وجود متطلب أو أمر أو ميزة معلنة أنها اختُبرت عملياً على جميع الأجهزة.

## نطاق البحث

### داخل النطاق
- أدوات Windows الجاهزة ومكتبات Android USB/ADB ذات الصلة.
- إعادة استخدام مشاريع GitHub والمكونات القائمة قبل تنفيذ بدائل جديدة.
- إتاحة وظائف البرنامج لوكلاء الذكاء الاصطناعي عبر MCP، بما في ذلك Codex، بصلاحيات مضبوطة.
- اكتشاف الهاتف وقراءة المعلومات بحسب وضع الاتصال، والتحويل بين الأوضاع حيث يوجد دليل موثوق.
- مقارنة الأدوات مفتوحة المصدر والتجارية وتجارب المستخدمين.
- إدارة التطبيقات عبر ADB على USB وWireless، وفحص APK/APKS وABI.
- إعدادات DNS وحجب الإعلانات مع الفصل بين Android Private DNS وDNS التقليدي وحلول VPN المحلية.
- بيانات التطبيقات مثل First Install Time وLast Update Time وInstaller Source والفلاتر المرتبطة بها.
- تشخيص وإصلاح تعريفات Windows من Microsoft وGoogle والشركات المصنّعة الرسمية.

### خارج النطاق حالياً
- قراءة أوضاع Qualcomm وMediaTek وبروتوكولاتها.
- مقارنة تراخيص الأدوات.
- تنفيذ تغييرات فعلية على الهواتف أو تعريفات Windows دون موافقة اختبار مستقلة.

## قواعد تقييم المعلومات

- **موثق رسمياً:** ما تنص عليه وثيقة Android/AOSP أو Microsoft أو Google أو الشركة المصنّعة.
- **موجود في الكود:** التنفيذ ظاهر في المصدر، لكن ذلك لا يثبت نجاحه وقت التشغيل.
- **معلن من المطور:** ميزة منشورة في صفحة الأداة أو سجل إصدار، ولم تُختبر مستقلاً.
- **تجربة مجتمع:** تقرير مستخدم محدود بالجهاز والإصدار والظروف المذكورة.
- **مختبر فعلياً:** اختبار مسجل ببيئته وخطواته ونتيجته؛ لا يعمم خارج نطاقه.
- **غير متحقق / لم يُختبر:** لا يوجد دليل كافٍ أو لم يُنفذ الاختبار.

التفاصيل الكاملة لهذه التصنيفات موجودة في [منهجية البحث](docs/RESEARCH-METHODOLOGY.md).

## مبادئ هندسية إضافية

1. نبحث عن المشاريع والمكتبات القائمة أولاً، ونفضل إعادة الاستخدام عبر واجهات واضحة قبل بناء بديل من الصفر.
2. تشترك واجهة البرنامج وMCP في طبقة الخدمات نفسها؛ ولا يحصل وكيل الذكاء الاصطناعي على صلاحيات كتابة أو Shell مفتوحة افتراضياً.

## مبادئ السلامة

1. التشخيص يسبق الإصلاح؛ لا تفترض أن كل فشل اتصال سببه تعريف Windows.
2. لا تثبّت تعريفاً إلا بعد مطابقة Hardware IDs والتحقق من المصدر والتوقيع.
3. لا تحذف Driver Packages عامة أو مشتركة لمجرد ظهور مشكلة في هاتف واحد.
4. لا تغيّر DNS أو إعدادات الهاتف دون حفظ الحالة الأصلية وموافقة منفصلة.
5. افصل بين اكتشاف USB، وربط التعريف، وموافقة Android، ونجاح بروتوكول الاتصال.
6. لا تسجل IMEI أو Serial أو رموز الاعتماد في التقارير المنشورة.
