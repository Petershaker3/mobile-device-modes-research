# Threat Model — منصة أدوات أجهزة Android

> **الغرض:** تحويل سياسات الأمان المتناثرة في [00 §6](docs/00-PRODUCT-BASELINE.md) و[02 §20](docs/02-tool-landscape-and-market-research.md) إلى نموذج تهديد قابل للتنفيذ: أصول محددة، هجوم محتمل، ضابط مبني، واختبار يثبته.
>
> **الحالة:** التهديدات والضوابط **مصمَّمة**؛ لم يُختبر أي ضابط على تشغيل فعلي. كل صف في §5 مرتبط باختبار مطلوب.

**التاريخ:** 13 نوفمبر 2026

---

## 1. حدود النظام والأصول

```
[ الإنترنت ] --HTTPS--> [ Provider Adapters ] --+
                                                |
[ MCP Client (Codex) ] --STDIO--> [ MCP Server ]+--> [ Application Services ]
                                                        |
[ Desktop (WPF) ] --------------------------------------+
                                                        |
                                        +---------------+---------------+
                                        |                               |
                                [ ADB / Platform Tools ]      [ Windows PnP/WPD ]
                                        |                               |
                                  [ Android Device ]           [ Device Manager ]
```

| الأصل | لماذا يهم | مستوى الحساسية |
|---|---|---|
| **الجهاز نفسه** | عمليات كتابة قد تُفقد بيانات أو تُعطّل تطبيقاً | حرج |
| **ملفات المستخدم على الجهاز** | صور/مستندات لا تُستعاد | حرج |
| **بيانات التطبيقات الخاصة** | لا يمكن الوصول إليها أصلاً؛ أي محاولة اختراق = خرق | حرج |
| **بيانات الهوية** (IMEI/IMSI/MAC/سيريال) | تعريف شخصي + أثر تتبّع | مرتفع |
| **بيانات السجلات (logcat/bugreport)** | قد تحتوي محتوى رسائل/حسابات/مواقع | مرتفع |
| **سجل التدقيق** | دليل ما حدث؛ تلاعب به = فقدان المساءلة | مرتفع |
| **ملفات الحزم المنزّلة** | مصدر كود يُثبَّت على جهاز المستخدم | مرتفع |
| **تعريفات Windows** | تثبيت تعريف خاطئ = جهاز معطّل على مستوى النظام | مرتفع |
| **جهاز المستخدم (Windows)** | SSRF/كتابة مسارات عشوائية/تنفيذ أوامر | حرج |

**خارج حدود التهديد (معلن صريحاً):** مستخدم بصلاحيات Administrator محلية يعيد بناء الـexe أو يعدّل قاعدة البيانات يدوياً. المنتج لا يدّعي مقاومة مالك الجهاز.

## 2. الجهات المعادية

| الجهة | الدافع | القدرة |
|---|---|---|
| **مصدر حزم خبيث** (APKPure mirror / رابط مُعاد توجيهه / أرشيف ملفَّق) | تثبيت كود على جهاز الفني | يتحكم في bytes الملف والـredirects |
| **وكيل AI (Codex) مُسيء الاستخدام أو مُخترَق** | تنفيذ عملية كتابة/حذف بدون علم المستخدم، أو استخراج بيانات | يستدعي أدوات MCP بأي ترتيب وبأي معدل |
| **موقع ويب مفتوح في المتصفح أثناء الاستخدام** | CSRF على خدمة محلية / استغلال localhost | يستطيع إرسال HTTP إلى localhost |
| **جهاز أندرويد خبيث** (أو مُخترَق) | إرجاع مخرجات مضلِّلة، مخرجات ضخمة، تسريب، إيهام بنجاح | يتحكم في كل bytes قادمة من shell/sync |
| **تطبيق أندرويد خبيث** على الجهاز | استغلال أشياء تُقرأ عند تصدير/فحص الحزم | يتحكم في manifest والموارد والأسماء |
| **حزمة تعريف مُزيَّفة** | تثبيت driver ضار | تنتحل اسم OEM |
| **شخص آخر على نفس الجهاز** (جلسة Windows مختلفة) | قراءة سجلات/نسخ بيانات | وصول لملفات `%LOCALAPPDATA%` حسب ACL |

## 3. مسارات الهجوم والضوابط

### T1 — تنفيذ أوامر عبر حقن shell (Argument/Script Injection)

**كيف:** اسم ملف أو package id أو مسار يحوي `'` أو `;` أو `$()` فيُدمج في سلسلة shell على الجهاز.
**الضابط:**
- العقود لا تسمح بأي خطوة تحمل سلسلة shell واحدة؛ `plan.steps[].command.argv[]` مصفوفة ([19 §3.3](docs/19-SHARED-CONTRACTS.md)).
- `ShellQuoter` مركزي واحد: تغليف مفرد مع `'\''` (النمط المُدقَّق في [13](docs/13-source-revalidation-adb-file-core.md)).
- أي مسار يصل بين quotes يُرفض إن احتوى بايت تحكم (`\x00`–`\x1F`).
**الاختبار:** corpus أسماء ملفات: `a'b`, `a;rm -rf /`, `$(reboot)`, `a b`, `ملف عربي.jpg`, newline داخل اسم.

### T2 — حذف/كتابة خارج المسار المسموح (Path Traversal / Root Deletion)

**كيف:** `rm -rf` على مسار نسبي أو على `""` يُنتج `/`؛ أو `..` في مسار محلي يخرج عن مجلد الوجهة.
**الضابط:**
- تحويل كل مسار إلى `CanonicalRemotePath` قبل الاستخدام؛ رفض `/`، `/sdcard`، و`/data` كأهداف حذف.
- قائمة `ProtectedPrefixes`: `/`, `/system`, `/vendor`, `/data`, `/data/data`, `/data/system`, `/metadata`, `/boot`, `/persist`.
- المسار المحلي: `Path.GetFullPath` + التأكد أنه داخل `DestinationRoot` المصرَّح (لا `\\?\`, لا UNC، لا reparse point).
**الاختبار:** حالات `""`, `/`, `//`, `/sdcard/../..`, `C:\..\Windows`, junction إلى مجلد آخر.

### T3 — Zip Slip / Zip Bomb / Symlink Escape

**كيف:** أرشيف APKS/APKM/XAPK يحتوي `../../`، أو نسبة ضغط هائلة، أو symlink يخرج من مجلد الاستخراج.
**الضابط (من [18 §3](docs/18-ENGINEERING-DECISIONS.md)):**
- حد 100,000 entry، نسبة 100:1، 4 GiB مفكوك، عمق 32، طول مسار 4096.
- لكل entry: رفض المسار المطلق، رفض `..`, رفض `:` في اسم على Windows، رفض symlink/hardlink.
- الاستخراج إلى مجلد باسم `operation_id` فقط، والتنظيف يمس هذا المجلد حصراً.
**الاختبار:** 8 fixtures خبيثة موثقة في [corpus/](corpus/README.md).

### T4 — SSRF وتنزيل من مصدر غير متوقع

**كيف:** رابط تنزيل يُوجَّه إلى `http://127.0.0.1:5037` (adb server) أو خدمة داخلية.
**الضابط:** allowlist نطاقات لكل provider + رفض IPs الخاصة (بما فيها المكافئ IPv6) + إعادة تحقق بعد كل redirect (حد 5) + منع HTTPS→HTTP.
**الاختبار:** جدول عناوين يقبل العامة ويرفض 12 حالة خاصة.

### T5 — **استدعاء MCP بدون علم المستخدم** (المسار الأخطر في المنتج)

**كيف:** وكيل AI يستدعي `install` أو `file.delete` مباشرة، أو يطلب موافقة على خطة ثم ينفّذ خطة أخرى.
**الضابط (ثلاث طبقات، لا طبقة واحدة):**
1. **لا أدوات كتابة في V1 من MCP** ([15 §7](docs/15-source-revalidation-mcp-codex.md)). الأدوات المكشوفة ReadOnly فقط.
2. **عند فتح الكتابة:** الموافقة تُطلب من **سطح Desktop**، لا من داخل الـMCP session. الوكيل يحصل على `AwaitingApproval` فقط.
3. **الموافقة مرتبطة بـ`scopeDigest`** ([19 §3.3](docs/19-SHARED-CONTRACTS.md))؛ تغيير بايت = إبطال. وتنتهي صلاحية الـtoken بعد 5 دقائق.
**الاختبار:** استدعاء أداة كتابة يُرجع `PolicyBlocked`؛ تغيير حقل واحد في الخطة يُرجع `ApprovalExpired`/mismatch.

### T6 — CSRF على خدمة محلية

**كيف:** صفحة ويب في المتصفح ترسل POST إلى `http://localhost:<port>` لواجهة/خدمة.
**الضابط:** الـMCP يعمل عبر **STDIO** فقط، لا HTTP. أي خدمة HTTP مستقبلية (مثل واجهة اختيارية) تفرض:
- ربط على `127.0.0.1` فقط.
- تحقق `Origin`/`Sec-Fetch-Site` ورفض أي origin غير فارغ.
- token عشوائي لكل جلسة يُمرَّر في header مخصّص (لا cookie)، لأن الـcookie يُرسَل تلقائياً.
**الاختبار:** طلب بلا token = 403؛ طلب بـ`Origin: https://evil.example` = 403.

### T7 — مخرجات جهاز ضخمة أو مُلفَّقة (Resource Exhaustion / Deception)

**كيف:** `getprop` يُرجع 50 MB، أو `logcat` لا ينتهي، أو `pm list packages` يُرجع أسطر مكررة تُشبع الذاكرة.
**الضابط:** كل قراءة لها سقف بايتات وأسطر ومهلة ([18 §3](docs/18-ENGINEERING-DECISIONS.md))؛ التجاوز = `LimitExceeded` صريح لا قص صامت. `rawEvidence` محدود 8 KB ويُعلَّم `truncated`.
**الاختبار:** fixtures بمخرجات 10 MB وسطور بلا نهاية (بدون newline).

### T8 — إيهام بالنجاح (False Success)

**كيف:** الجهاز يُرجع "Success" دون تنفيذ، أو `exitCode=0` مع `Failure [INSTALL_FAILED_...]` في النص.
**الضابط:** `result.ok` لا يُشتق من الـexit code؛ يلزم `verification.verified=true` من قراءة مستقلة ([19 §3.7](docs/19-SHARED-CONTRACTS.md)). رسمياً: `ok=true` مع `verified=false` مرفوض في الـschema.
**الاختبار:** fixture يُرجع `Success` ثم `pm list` لا يجد الحزمة ⇒ النتيجة `Failed`، لا `Succeeded`.

### T9 — تسريب بيانات حساسة عبر السجلات

**كيف:** logcat يحتوي رسالة SMS/بريد/توكن؛ bugreport يحتوي serial ومواقع؛ السجل يُصدَّر ويُشارَك.
**الضابط:** تنقيح تلقائي للأنماط (IMEI-like 15 رقم، MAC، بريد، Bearer، serial) + **شاشة معاينة تنقيح** قبل أي تصدير + الـbugreport موسوم "حساس" افتراضياً.
**الاختبار:** corpus سجلات فيه 12 نمطاً حساساً؛ التحقق أن الصادر المنقَّح لا يحوي أياً منها.

### T10 — حزمة تعريف مُزيَّفة

**كيف:** موقع "driver updater" يقدّم INF/SYS موقّعاً بمفتاح مشبوه أو غير موقّع.
**الضابط:** V1 **لا يثبّت تعريفات** — تشخيص فقط ([18 §5](docs/18-ENGINEERING-DECISIONS.md)). وأي لاحق: مطابقة Hardware IDs + تحقق توقيع + مصدر رسمي فقط + rollback plan + elevation صريح.
**الاختبار:** لا ينطبق في V1؛ اختبار تصميم: حزمة غير موقّعة تُرفض في مرحلة الفحص.

### T11 — استغلال تطبيق أندرويد خبيث عند فحص الحزمة

**كيف:** manifest/موارد مصممة لتفجير parser (aapt dump ضخم، اسم حزمة بطول هائل، موارد متشابكة).
**الضابط:** كل parser يعمل على دفق محدود لا على تحميل كامل؛ حدود أطوال الحقول؛ `aapt2` يعمل كعملية منفصلة بمهلة وسقف مخرجات؛ لا تنفيذ أي شيء من الحزمة.
**الاختبار:** fixtures: manifest بطول 1 MB، 10,000 split، اسم حزمة 4 KB.

### T12 — تلاعب بسجل التدقيق

**كيف:** تعديل قاعدة البيانات/الملف لإخفاء عملية حدثت.
**الضابط:** إلحاقي فقط على مستوى المستودع + سلسلة hash (`previousEventHash`)؛ أي انقطاع يرفع `AuditIntegrityViolation` ويُعرض للمستخدم. لا "إصلاح صامت".
**الاختبار:** تعديل سجل بالمنتصف ⇒ الكشف عند القراءة التالية.

### T13 — جلسة Windows أخرى تقرأ بيانات

**كيف:** مستخدم آخر على نفس الجهاز يقرأ `%LOCALAPPDATA%\...\state`.
**الضابط:** مجلد الحالة ACL للمستخدم الحالي؛ السجلات نفسها منقّحة؛ البيانات الحساسة (bugreport) موسومة ومحدودة الاحتفاظ (14 يوماً افتراضياً).
**الاختبار:** مراجعة ACL على مجلد الحالة (يدوي في V1، مؤتمت لاحقاً).

## 4. ما لا نغطيه بقرار

| البند | السبب |
|---|---|
| مقاومة مالك الجهاز بصلاحيات Administrator | خارج نموذج التهديد؛ لا يمكن ضمانه |
| root / Magisk | خارج النطاق؛ أي مسار `su` مرفوض |
| تفليش/كتابة أقسام | خارج النطاق بقرار [00](docs/00-PRODUCT-BASELINE.md) |
| بروتوكولات Qualcomm/MediaTek | خارج النطاق |
| حماية ضد جهاز يعيد تعريف نفسه كـUSB آخر (Malicious USB Device) بيد مادية | V1 لا يفرض USB allowlist صارم؛ يُسجَّل كخطر مقبول ومؤجل |

## 5. مصفوفة الضابط ↔ الاختبار

| التهديد | الضابط موجود في الكود؟ | اختبار مكتوب؟ | اختبار يعمل الآن؟ |
|---|---|---|---|
| T1 Command injection | ❌ | مُعرَّف (§3) | ❌ |
| T2 Path traversal | ❌ | مُعرَّف | ❌ |
| T3 Archive bombs | ❌ | fixtures موصوفة في [corpus](corpus/README.md) | ❌ |
| T4 SSRF | ❌ | مُعرَّف | ❌ |
| T5 MCP write bypass | ✅ قرار (§4 V1 = read-only) | مُعرَّف | ❌ |
| T6 CSRF | ✅ قرار (STDIO فقط) | مُعرَّف | ❌ |
| T7 Resource exhaustion | ✅ أرقام في [18 §3](docs/18-ENGINEERING-DECISIONS.md) | مُعرَّف | ❌ |
| T8 False success | ✅ مفروض في schema | ✅ **نعم** (حالة سلبية #5) | ✅ **نعم** |
| T9 Data leakage | ✅ قرار التنقيح | مُعرَّف | ❌ |
| T10 Fake driver | ✅ قرار (لا تثبيت في V1) | لا ينطبق | — |
| T11 Malicious package | ❌ | مُعرَّف | ❌ |
| T12 Audit tampering | ✅ مفروض في schema | مُعرَّف | ❌ |
| T13 Local session | ✅ قرار | مُعرَّف | ❌ |

**القراءة الصادقة للجدول:** ضابطان فقط مُنفَّذان وقابلان للفحص اليوم (T8 عبر العقود، وT5/T6/T10/T12 كقرارات معمارية). الباقي تصميم — **لا يُوصف بأنه محمي**.

## 6. ترتيب التنفيذ الموصى به

1. **T1 + T2** مع أول كود ADB (لا معنى لبناء أمر دون quoting صحيح).
2. **T8** — مكتمل عبر العقود؛ يُوسَّع بمحرك `Verification`.
3. **T3 + T11** مع أول parser أرشيف.
4. **T7** مع أول تنفيذ فعلي (الثوابت موجودة).
5. **T9** مع Logcat/Bugreport.
6. **T5/T6** عند فتح MCP للكتابة (ليس في V1).
7. **T12** مع `AuditStore`.
8. **T4** مع أول provider تنزيل.

**آخر تحديث:** 13 نوفمبر 2026 — **الحالة:** نموذج تهديد مُصمَّم؛ ضابطان مُنفَّذان (أحدهما باختبار يعمل)، والباقي تصميم لم يُختبر.
