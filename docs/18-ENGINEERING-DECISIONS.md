# القرارات الهندسية التنفيذية

> **الغرض:** إغلاق بنود [00 §9.2](00-PRODUCT-BASELINE.md) التي بقيت "قرارات تنفيذ لا تزال مفتوحة". كل قرار هنا **قابل للقياس والتغيير بمراجعة**، وليس نصيحة عامة. كل رقم هنا يجب أن يظهر كثابت مسمّى في الكود، لا كرقم مبعثر.
>
> **الحالة:** معتمدة كأساس للتنفيذ، **غير مختبرة على جهاز**. أي رقم أدناه يُوصف بأنه "افتراضي مبدئي" حتى يثبته قياس Runtime.

**التاريخ:** 13 نوفمبر 2026 — **يعتمد على:** [ADR-0001](17-adr-0001-stack-decision.md)

---

## 1. المعمارية ونطاق الأنظمة

| البند | القرار | ملاحظة |
|---|---|---|
| معمارية Windows | **`win-x64` أولاً.** `win-arm64` مؤجل حتى يثبت وجود جهاز اختبار ARM64 | بناء `AnyCPU` ممنوع لأن الـP/Invoke structs مرتبطة بالمعمارية |
| الحد الأدنى لـWindows | Windows 10 1809 (build 17763) فما فوق | يطابق أدنى مستوى تدعمه APIs المستخدمة؛ Windows 11 مدعوم صريحاً |
| الحد الأدنى لـAndroid | API 24 | كل feature يمر بـ`android_api_range` في `Capability`؛ لا feature تُفعَّل بالافتراض |
| نشر المنتج | `self-contained` x64 + إصدار framework-dependent | لا نشر `single-file` في V1: يكسر تشخيص crash dumps ويبطئ الإقلاع |
| UI thread | كل استدعاء خدمة من الـUI يمر عبر `await`؛ لا `.Result`/`.Wait()` | قاعدة قابلة للفحص آلياً (analyzer) |

## 2. سياسة إصدارات الأدوات والاعتماديات

| المكوّن | المصدر | طريقة التثبيت | التحقق |
|---|---|---|---|
| Android Platform Tools (`adb.exe`) | Google، tagged release | **لا تُضمَّن في المستودع.** تُنزَّل في أول تشغيل إلى `%LOCALAPPDATA%\<App>\tools\platform-tools\<version>\` | SHA-256 مثبت في manifest داخلي + توقيع Google حيث يتوفر |
| AdvancedSharpAdbClient | NuGet | `PackageReference` مع **نسخة مثبتة بلا `*`** | `packages.lock.json` مُلتزَم في المستودع |
| bundletool | GitHub releases (Google) | تنزيل عند الحاجة فقط (مسار APKS/AAB) | SHA-256 + نسخة مثبتة؛ Java runtime يُكتشف ولا يُثبَّت تلقائياً |
| apksigner / aapt2 | Android SDK build-tools | غير مضمّنة؛ capability تُقاس عند التشغيل | يجب ألا يتوقف أي مسار أساسي على وجودها |
| CsWin32 | NuGet | `PackageReference` | يُولّد كود P/Invoke وقت البناء؛ نتيجة التوليد تُراجَع في diff |

**قواعد:**
- لا `PackageReference` بنسخة عائمة أو `latest`.
- كل تنزيل أداة يمر عبر [سياسة التنزيل (§6)](#6-سياسة-التنزيل-والتكامل-الشبكي) ويسجَّل في سجل التدقيق.
- تحديث أداة = تغيير manifest + إعادة تشغيل corpus القبول، لا "تحديث تلقائي".
- عند فشل التحقق من hash: **رفض التشغيل**، لا تحذير فقط.

## 3. المهلات والحدود (افتراضيات مبدئية قابلة للقياس)

كل قيمة ثابت مسمّى في `Limits.cs`، وكل تجاوز يُسجَّل في التدقيق كـ`limit_overridden`.

| العملية | المهلة الافتراضية | الإلغاء | ملاحظة |
|---|---:|---|---|
| `adb devices` / device enumeration | 10 ث | نعم | تتكرر دورياً كل 2 ث أثناء المراقبة |
| استعلام `getprop` واحد | 15 ث | نعم | |
| قراءة معلومات جهاز كاملة (كل الحقول) | 90 ث | نعم | كل حقل له حالته المستقلة؛ الفشل الجزئي لا يُسقط التقرير |
| أمر `shell` قراءة قصير | 30 ث | نعم | |
| `dumpsys <service>` واحد | 45 ث | نعم | بعض الخدمات بطيئة على أجهزة ممتلئة |
| تصوير `logcat` مباشر | **بلا مهلة كلية** | نعم (إلزامي) | بحد أقصى مساحة/مدة لكل جلسة |
| جلسة logcat واحدة | 8 ساعات أو 512 MiB (أول ما يتحقق) | نعم | rotation عند 64 MiB/ملف |
| `bugreportz` | 30 دقيقة | نعم | progress من الجهاز؛ إن لم يصل progress 60 ث → تحذير |
| نقل ملف | مهلة خمول 60 ث (لا مهلة كلية) | نعم | الخمول يُقاس بلا بايتات متحركة |
| ملف واحد | ≤ 8 GiB | — | فوق ذلك يُرفض بخطأ واضح لا بمحاولة |
| `install` / `install-multiple` | 10 دقائق | نعم | بعدها `OutcomeUnknown` → reconciliation |
| رفع session (split set) | 15 دقيقة | نعم | |
| نشر APKS عبر bundletool | 15 دقيقة | نعم | قتل شجرة الـprocess كاملة |
| `push` إلى `/data/local/tmp` لملفات التثبيت | 5 دقائق | نعم | |
| عملية تعريف Windows (PnP scan) | 60 ث | نعم | لا تعديل للنظام في V1 |
| إنشاء backup archive محلي | بلا مهلة كلية، خمول 120 ث | نعم | |

**حدود الموارد العامة:**

| المورد | الحد |
|---|---|
| أقصى عملية متزامنة لكل جهاز | 1 عملية مؤثرة + قراءات متعددة مسموحة |
| أقصى عملية متزامنة إجمالاً | 8، مع طابور |
| ذاكرة وسيطة لـlogcat | 32 MiB ring buffer افتراضي، قابل للتغيير ضمن [8, 256] MiB |
| عدد entries في ZIP يُفتح | 100,000 |
| نسبة膨胀 المضغوط | 100:1 كحد أقصى، وإجمالي 4 GiB مفكوك |
| عمق مسار داخل أرشيف | 32 مستوى، طول باث 4096 |

**قاعدة `OutcomeUnknown`:** أي عملية مؤثرة تجاوزت مهلتها تُصبح `OutcomeUnknown` **ولا يُعاد تشغيلها تلقائياً**. تُنفَّذ `Reconcile()` أولاً: تقرأ حالة الجهاز الفعلية (هل الحزمة موجودة؟ هل الملف موجود بحجمه؟) ثم تُقرر `Succeeded` / `Failed` / `NeedsReconciliation`.

## 4. الاحتفاظ بالسجلات والخصوصية

| البيانات | الافتراضي | أقصى | التنقيح |
|---|---|---|---|
| Audit log (عمليات ونتائج) | 90 يوماً | 365 | بلا serial كامل: يُخزَّن hash قصير + آخر 4 أحرف |
| مخرجات الأوامر الخام | 7 أيام | 30 | تنقيح تلقائي لأنماط IMEI/MAC/email/token |
| Logcat المحفوظ | 7 أيام | بلا حد افتراضي (المستخدم يقرر) | لا تنقيح تلقائي — ملف المستخدم ملكه، والتقرير المصغّر هو ما يُنقَّح |
| Bugreport | 14 يوماً | 90 | يُعلَّم "حساس" افتراضياً؛ يُطلب تأكيد قبل أي تصدير/مشاركة |
| ملفات staging المؤقتة | تُحذف عند نهاية العملية | 24 ساعة (منظّف دوري) | التنظيف يمس فقط ما أنشأته العملية (`operation_id` في اسم المجلد) |
| سجل الأخطاء/التشخيص | 30 يوماً | 90 | بلا مسارات مستخدم كاملة |

**قواعد:**
- لا يُسجَّل IMEI/IMSI/MAC/Serial الجهاز الكامل في أي سجل افتراضي.
- إن احتاج المستخدم تصدير تقرير: تظهر **شاشة معاينة تنقيح** قبل الكتابة إلى الملف، ويمكنه إلغاء التنقيح صراحةً مع تحذير.
- مكان التخزين: `%LOCALAPPDATA%\<App>\state\` — وليس بجوار الـexe (يمنع مشاكل UAC/Program Files).

| نقل/حذف/إعادة تسمية ملفات | **مسموح** | حماية من حذف root/jailed paths؛ لا حذف متكرر بلا معاينة قائمة |

| نسخ بيانات التطبيقات الخاصة | **ممنوع** | بلا مسار نظام موثق ([11](11-backup-restore-boundaries.md)) |

## 6. سياسة التنزيل والتكامل الشبكي

| القاعدة | التفصيل |
|---|---|
| TLS | HTTPS فقط؛ شهادة غير صالحة = رفض، لا "تجاهل" |
| Redirects | 5 كحد أقصى؛ لا ينزل من HTTPS إلى HTTP؛ يُعاد التحقق من المضيف بعد كل redirect |
| SSRF | رفض `localhost`, `127.0.0.0/8`, `10/8`, `172.16/12`, `192.168/16`, `169.254/16`, `::1`, `fc00::/7`, وأي IP حرفي غير عام |
| النطاقات المسموحة | قائمة allowlist لكل Provider adapter؛ لا wildcard عام |
| حجم التنزيل | يُتحقق من Content-Length مقابل حد معلن؛ تجاوز = قطع |
| hash | عند توفره من المصدر: تحقق إلزامي. عند غيابه: يُعرض "غير قابل للتحقق" بوضوح، ولا يُدَّعى سلامة |
| cookies/tokens | لا تُشارك بين providers؛ لا تُسجَّل |
| التنزيل ≠ التثبيت | ملف يُنزَّل لا يُثبَّت تلقائياً أبداً ([00 §5](00-PRODUCT-BASELINE.md)) |

## 7. الاختبار وملف الاعتماد

| المستوى | يعمل في CI الافتراضي | يحتاج جهازاً | يحتاج Windows |
|---|---|---|---|
| Unit (خدمات، سياسات، مهلات) | ✅ | ❌ | ❌ (يمكن على أي OS إن تجنّبنا APIs Windows) |
| Parser/Fixture (getprop، df، logcat، manifest، toc.pb) | ✅ | ❌ | ❌ |
| Contract tests (schemas + approval flow) | ✅ | ❌ | ❌ |
| Integration (ADB عبر fake socket / sidecar مزيّف) | ✅ | ❌ | جزئياً |
| Runtime (adb.exe حقيقي + محاكي) | ❌ | محاكي | ✅ |
| Hardware | ❌ | ✅ | ✅ |

**بوابة الدمج:** لا يُدمج تغيير يقلل التغطية في `Services/` ولا يمر `dotnet test` و`dotnet format --verify-no-changes` وفحص الـschemas.

## 8. المخاطر المفتوحة المقبولة

| المخاطرة | التخفيف | متى تُراجع |
|---|---|---|
| كل أرقام §3 غير مقاسة على جهاز | مسمّاة كثوابت + تجاوز مسجَّل | بعد أول 20 عملية على جهاز حقيقي |
| AdvancedSharpAdbClient بلا مهلة على القناة (فجوة موثقة في [13](13-source-revalidation-adb-file-core.md)) | كل استدعاء يُغلَّف بـ`CancellationToken` + قطع الاتصال كوسيلة إلغاء | أثناء Host Core PoC |
| `win-arm64` غير مدعوم | معلن صريحاً في صفحة المتطلبات | عند توفر جهاز |
| الاعتماد على `adb.exe` خارجي لبعض المسارات | capability check قبل الاستخدام + رسالة قابلة للتنفيذ | عند بناء Module ADB |
| تنقيح السجلات قد يخفي معلومات تشخيص لازمة | إمكانية إلغاء التنقيح صراحةً + نسخة كاملة محلية فقط | بعد أول بلاغ دعم حقيقي |
