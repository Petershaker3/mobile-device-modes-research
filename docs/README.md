# فهرس الوثائق

هذا الفهرس منظم حسب رحلة فهم المنتج، ثم تفاصيل كل مجال، ثم أدلة البحث. ابدأ دائماً بـ[خط الأساس ومتطلبات المنتج](00-PRODUCT-BASELINE.md) لتعرف ما الذي نبنيه وما الذي تم اعتماده وما الذي ما زال غير متحقق.

## 1. وثائق القرار والحوكمة

1. [00 — خط الأساس ومتطلبات المنتج](00-PRODUCT-BASELINE.md) — تعريف المنصة متعددة المحاور، بيئة التشغيل، القرارات والأولويات، المعمارية، التثبيت، الأمان، الحالة والخطوات التالية.
2. [مصفوفة تغطية البحث والوظائف](05-RESEARCH-COVERAGE-MATRIX.md) — تربط كل وظيفة بالوثائق والأدلة والمشاريع الجاهزة والفجوات؛ وهي نقطة البداية لتحديد ما ينقص البحث فعلاً.
3. [منهجية البحث وضبط جودة الأدلة](RESEARCH-METHODOLOGY.md) — درجات الأدلة، حالات التنفيذ والاختبار، بطاقات تقييم الأدوات، سجل الاختبارات، إعادة الاستخدام، سياسة MCP والأمان.

## 2. وثائق المجالات الوظيفية

4. [01 — الاتصال وقراءة المعلومات والتحويل بين الأوضاع](01-connectivity-protocols.md) — USB، ADB، Fastboot/Fastbootd، MTP/WPD، Samsung AT/Download، Xiaomi Mi Assistant، Huawei/Honor، انتقالات الأوضاع، وحالات النتائج.
5. [03 — إدارة تطبيقات Android والشبكة عبر ADB](03-app-management-and-network.md) — إدارة التطبيقات، USB/Wireless، البحث والفلاتر، تواريخ التثبيت والتحديث، Installer Source، DNS، وأولوية محرك التثبيت.
6. [04 — تشخيص وإصلاح تعريفات Android على Windows](04-windows-driver-diagnostics.md) — SetupAPI/PnP، Hardware IDs، مصادر التعريفات الرسمية، الإصلاح، التراجع، واختبارات القبول.
7. [06 — معلومات نظام Android والجهاز](06-android-system-information.md) — كتالوج حقول الجهاز والبناء والـABI والذاكرة والتخزين والطاقة، مع تدقيق مشاريع GitHub ومصادر القراءة وحدود API 24+.
8. [07 — جرد السوفتوير والفريموير](07-firmware-software-inventory.md) — معلومات OTA metadata وpayload.bin وpartition manifests وAVB/vbmeta، مع فصل الفحص المحلي عن أي تحديث للجهاز.
9. [08 — معلومات التخزين والأقسام](08-storage-partition-information.md) — filesystem usage، physical/logical/dynamic partitions، super metadata، A/B وVirtual A/B، وأدوات AOSP للقراءة فقط.
10. [09 — إدارة ملفات Android والنقل](09-device-file-management.md) — ADB وMTP/WPD وvirtual drive، dual-pane، نقل الملفات، Unicode، الإلغاء والتحقق، ومراجعة مشاريع GitHub.
11. [10 — تشخيص Android والسجلات](10-android-diagnostics-and-logs.md) — Live Logcat، التسجيل، Bugreport، dumpsys، Dropbox، Perfetto، تحليل الملفات الكبيرة، ومراجعة مشاريع GitHub.
12. [11 — حدود النسخ الاحتياطي والاستعادة](11-backup-restore-boundaries.md) — تصنيف أنواع النسخ وحدود adb backup وAuto Backup، وتدقيق incremental backup وملفات .ab واستعادة الملفات بأمان.

## 4. حالة الوثائق المستقلة

تم إنشاء جميع الوثائق المستقلة المقترحة من 06 إلى 11. لا توجد وثائق مجال مستقلة أخرى مخطط لها حالياً؛ أي فجوات لاحقة ستضاف إلى الوثيقة المناسبة أو إلى مصفوفة التغطية.

## 5. القرارات الحالية المختصرة

- بيئة التشغيل المعتمدة: Windows 10/11 وAndroid 7.0 (API 24) فأحدث.
- المنتج منصة متعددة المحاور: اتصال وقراءة بيانات وأوضاع ومعلومات سوفتوير وإدارة تطبيقات وملفات وتشخيص وشبكة وتعريفات وMCP؛ تثبيت التطبيقات مسار أساسي داخل محور التطبيقات وليس تعريف المنتج كله.
- داخل محور التثبيت: APK وSplit APK وAPKS ضمن P0؛ APKM غير المشفر وXAPK/OBB توسعة لاحقة بعد الاختبار. الصيغ المشفرة أو مجهولة البنية مؤجلة.
- معمارية Windows الدقيقة ومصفوفة أجهزة/إصدارات Android للاختبار والاعتماديات والمهلات وسياسة الفشل ما زالت قرارات تنفيذية مفتوحة؛ نطاق أنظمة التشغيل نفسه محسوم.
- F-Droid مرشح لتكامل أصلي عبر فهارس موقعة؛ APKPure وAPKMirror عبر adapters مستقلة دون افتراض API عامة أو تجاوز حماية المواقع.
- كل الصيغ تمر عبر Format Detection وParser/Adapter وفحص أمني وتوافق، ثم Unified Install Engine.
- لا تحليل ELF متقدم ضمن شروط تثبيت V1؛ ويمكن بحثه كأداة تشخيص متقدمة ضمن محور معلومات السوفتوير.
- GUI وMCP يتشاركان Service Layer، مع Read-only افتراضياً وموافقة منفصلة للعمليات المؤثرة.
- لا قراءة Qualcomm/MediaTek، ولا مقارنة تراخيص.

## 6. قواعد القراءة والتحديث

- خط الأساس يملك **القرار الحالي**؛ ملف المجال يملك المتطلبات التفصيلية؛ ملف 02 يملك **سجل الأدلة ومراجعات المرشحين**؛ ملف 05 يملك **حالة التغطية والفجوات**.
- لا تكرر مراجعة مشروع أو نتيجة في عدة ملفات؛ أضف رابطاً إلى المصدر الأساسي.
- عند تغير قرار، حدّث خط الأساس وسجل سبب التغيير في ملف البحث المرتبط.
- لا تحوّل ادعاء مطور أو كود أو نجاح CI إلى ادعاء اختبار فعلي.
- لا تعتبر خانة [x] في قائمة توثيق دليلاً على اختبار Runtime ما لم يوجد سجل اختبار مطابق.
- كل اختبار فعلي يسجل الجهاز والموديل وإصدار Android وWindows والأداة وإصدارها والخطوات والنتيجة والأدلة بعد تنقيح البيانات الحساسة.

**الحالة:** الوثائق مرجع بحث وتصميم ومتطلبات؛ لا تمثل تطبيقاً منفذاً أو اعتماداً نهائياً للمكونات.

> **ملاحظة تنظيمية:** أرقام الأقسام داخل الملفات أرقام محلية وليست ترقيمًا موحدًا للمستودع. تم تصحيح تكرار الرقم 18 بين وثيقة إدارة التطبيقات ووثيقة التعريفات؛ قسم التعريفات أصبح 19. الروابط والمسارات هي المرجع الأساسي للتنقل.
